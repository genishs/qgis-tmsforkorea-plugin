changelog=
    4.0.1
        - Fix: Naver tile URIs not rendering on QGIS 4. Previous build
          aggressively percent-encoded the URL template (?, &, =, @ etc.)
          inside the XYZ URI; some QGIS 4 builds did not decode it back
          before substituting {z}/{x}/{y}, producing malformed tile
          requests. URI now mirrors QGIS's own xyz-connection dialog
          format (type=xyz first, raw URL template, only '&' encoded).
        - Add: Naver Cadastral layer is now registered (was deferred
          from 4.0.0 release scope).
        - Add: every TMS layer-add is now logged to "Log Messages >
          TMS for Korea" with the URL template, full URI, and validity
          status. Invalid layers also push a message-bar warning.
        - Phase 2 research: Kakao, Google, Bing all deferred indefinitely
          due to upstream policy (Kakao tile API blocked since 2025-10-20,
          Google Maps ToS requires session-token API + billing, Bing Maps
          for Enterprise closed to new keys since 2024-06-30). See
          MIGRATION.md for full notes.
    4.0.0
        - First stable release for QGIS 4.x (Qt6). Verified loading and
          tile rendering on QGIS 4.0.1 (Norrkoping).
        - Working layers: VWorld (Street/Gray/Satellite/Hybrid), Naver v5
          (Street/Hybrid/Satellite/Physical) via XYZ tiles with dynamic
          version-token discovery, OpenStreetMap Standard.
        - Removed legacy QtWebKit-based renderer and OpenLayers Overview
          dock (Qt6 has no QtWebKit).
        - Hardened readXml so legacy 3.x projects containing Kakao/NGII
          layers degrade gracefully instead of crashing.
        - About dialog uses lazy construction and Qt6-compatible enum
          spellings; pyrcc/pyuic generated files migrated to qgis.PyQt.
        - Kakao, NGII, Mango deferred to a future release (4.1+);
          Kakao/NGII require GDAL TMS minidriver work for their
          custom CRS tile schemes, Mango upstream is unreachable.
    4.0.0-beta3
        - Hotfix: Qt6 enum compatibility in ui_about_dialog.py
          (Qt.AlignCenter -> Qt.AlignmentFlag.AlignCenter,
           Qt.LinksAccessibleByMouse -> Qt.TextInteractionFlag.LinksAccessibleByMouse,
           QDialogButtonBox.Close -> QDialogButtonBox.StandardButton.Close, etc.)
          The fully-qualified spellings work under both PyQt5 and PyQt6.
        - About dialog now constructed lazily on first menu click instead
          of in plugin __init__, so any further Qt6 quirks cannot block
          plugin load.
    4.0.0-beta2
        - Hotfix: replace hardcoded PyQt5 imports in resources_rc.py and
          ui_about_dialog.py with qgis.PyQt so the plugin loads under Qt6.
          Tested against QGIS 4.0.1 (Norrkoping).
    4.0.0-beta1
        - Re-enabled Naver layers (Street, Hybrid, Satellite, Physical) as XYZ tiles
          with dynamic version-token discovery against Naver's style JSON; falls
          back to a known-good token if discovery fails. Cadastral deferred.
        - Added OpenStreetMap Standard layer
        - Fixed XYZ URI percent-encoding so tile URLs containing query strings
          (e.g. Naver's ?mt=...) are parsed correctly by the QGIS WMS provider
        - Hardened readXml against missing OSM fallback so 3.x projects with
          orphan Kakao/NGII layers degrade gracefully instead of crashing
        - Mango still unavailable (upstream server unreachable as of 2026-05-14)
    4.0.0-alpha1
        - First release for QGIS 4.x (Qt6)
        - Removed legacy QtWebKit-based renderer and OpenLayers Overview dock
        - VWorld layers functional as XYZ tile sources
        - Kakao, NGII deferred to a future release pending GDAL TMS minidriver
          support for EPSG:5181 / EPSG:5179 tile schemes
